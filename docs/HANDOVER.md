## Accounts, notifications and push

### What fires when (API)
| Event | E-mail | Push (Expo) | In-app feed |
|-------|--------|-------------|-------------|
| Sign up (e-mail or Google) | `welcome` | - | - |
| Password reset requested | `password-reset` (link `…/auth/reset-password#token=…`; answer is identical for unknown addresses) | - | - |
| Password changed / reset | `password-changed` | - | guest/host (bell: "Contraseña actualizada") |
| Booking paid | `booking-confirmation` (guest), `host-new-booking` (host) | guest + host | guest + host |
| Booking cancelled | `booking-cancellation` (guest), `host-booking-cancelled` (host) | guest + host | guest + host |
| Unpaid booking expired | `booking-cancellation` (guest) | guest | guest |
| Day before check-in (job every few hours) | `check-in-reminder` | guest | guest (shown from 07:00 Colombia time) |
| Invoice issued | `invoice-receipt` | - | - |
| Account deleted | `account-deleted` | - | - |

Guests can switch off: reminder e-mails, and push for bookings / reminders. Hosts can also switch off the e-mails and push for new and cancelled bookings of their properties (`GET/PATCH /notifications/preferences`, web `/account/notifications`, mobile Perfil > Preferencias de avisos). Booking confirmations, cancellations, receipts and every security e-mail are always sent. WhatsApp has no preference: the API sends no WhatsApp messages.

### Push
- Expo push (`api/src/lib/push.ts`), no secret needed unless Expo "enhanced security" is enabled (`EXPO_ACCESS_TOKEN`). Tokens are registered with `POST /notifications/push-token` and removed with `/notifications/push-token/unregister` (mobile does it on sign-out) or on account deletion. Tokens Expo reports as `DeviceNotRegistered` are deleted.
- Push only works once the EAS project exists: `eas init` (see the Expo account row in `mobile/RELEASE.md`) writes `extra.eas.projectId` into `app.json`. Until then the app skips registration silently (no crash, no error).
- The web app / PWA has no web push (`public/sw.js` has no push handler); its channels are the bell and e-mail.

### Host bookings
`GET /host/bookings?scope=upcoming|past|cancelled&page=` lists the bookings of the caller's own properties (paginated, 20 per page; the host never sees the guest's e-mail or phone). Web: `/host/bookings`. Mobile: Reservas tab of the host area. A guest account can become a host with `POST /auth/become-host` (web `/become-host`, mobile Perfil > Publica tu espacio).

### Tests
`cd api && TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/elevari_test npm test` runs the integration suites against a real, local PostgreSQL (migrations applied, Resend and Expo replaced by local mock servers; see `api/tests/harness.ts`). Without `TEST_DATABASE_URL` they are skipped. `npx vitest run tests/` (repo root) covers the web and mobile pure logic; `tests/mobile/api-errors.test.ts` imports the app's `mobile/lib/api.ts`, so it also needs `npm ci` inside `mobile/`, and `tsconfig.json` leaves that one file out of the web type check (the web build has no Expo packages). CI does not run these yet.

## Scene Backgrounds

Vector (no photographs) landscape that follows the visitor's local time of day: golden (5-6h, 16-18h), day (7-15h), night (19-4h). Full reference: `docs/design/SCENE_SYSTEM.md`.

### Source and outputs
`scripts/scene/` is the single source. `npm run scene:generate` writes `lib/scene/scene-data.ts`, `mobile/lib/scene-data.ts`, `components/scene/scene-themes.css` and `public/brand/email/banner.jpg`; commit them. `npm run scene:check` (part of `npm run ci:local`) fails when they are stale.

### Where it appears
- **Web:** `/auth/login`, `/auth/register`, `/auth/forgot-password`, `/auth/reset-password` (via `components/auth/AuthShell.tsx`), the home bands (`components/home/SceneBand.tsx`) and the catalog hero. The old `/registration` placeholder was removed and now redirects to `/auth/register`.
- **Mobile:** login and registration (`mobile/components/scene/SceneScreen.tsx`).
- **Email:** static `banner.jpg` hero in `api/src/lib/email-templates/layout.ts` (email clients cannot run SVG or animation).

### Features
- Layered ridges, lake reflection, pines, sun/moon, clouds, mist and embers with independent parallax depth
- Smooth cross-fade between themes; night adds stars and shooting stars
- Pointer parallax on web (mouse/pen), touch parallax on mobile
- Respects `prefers-reduced-motion` / reduce-motion, and pauses off screen, in hidden tabs and in the background

## Production Deployment (Hetzner)

### Despliegue automático (GitHub Actions)

Cada push a la rama `b-main` activa el pipeline de CI/CD que despliega automáticamente en Hetzner. También puedes desplegar manualmente desde la pestaña **Actions → Deploy to Hetzner Production → Run workflow**.

### Secrets requeridos en GitHub

Vaya a **Settings → Secrets and variables → Actions → New repository secret** y añada:

| Secret | Valor ejemplo |
|--------|--------------|
| `HETZNER_IP` | `2.29.165.225` |
| `HETZNER_USER` | `root` |
| `HETZNER_SSH_KEY` | Contenido completo de `~/.ssh/id_ed25519_elevari_hetzner` |

### `.env.production` (no commitear)

Este archivo es gitignorado y nunca se sube a GitHub. Copialo manualmente al servidor:

```bash
scp .env.production root@2.29.165.225:/opt/elevari/.env.production
```

### Flujo de deploy

1. Push a `b-main` (o clic en "Run workflow" en Actions)
2. CI corre: build API, build web, validar env staging, typecheck mobile
3. Si todo pasa, SSH a Hetzner y ejecuta:
   - `git pull origin b-main`
   - `npm run go-live:validate`
   - `npm run go-live:deploy` (build + docker compose up -d)
   - Health check: `curl http://localhost/health`

La app Android (APK) no se despliega con este flujo: se compila a mano con el workflow «Mobile APK» y la web la enlaza desde `/app`. Ver `mobile/RELEASE.md`.
